# 動態行程地圖（/live）設計

日期：2026-10-15
狀態：設計已與使用者逐項確認，待使用者審閱後交給新的 Opus 5.5 session 實作

## 目的

6 人（含 1 位長輩、3 位 20 多歲、夫妻）釜山 3 天自由行（2026/10/31–11/2）。現有 `/map` 只能看站點和站與站之間的直線，看不出時間、方向、現在在哪一站。
新頁面 `/live` 要讓人一眼看出：**現在在哪一站、下一站在哪個方向、多遠、車程多久、幾點要出發**，出發前可預覽，旅途中可即時跟著走。

## 已確認的決定

| 項目 | 決定 |
|---|---|
| 用途 | 兩種都要：**預覽模式**（出發前，拉時間軸）與**即時模式**（旅途中，手機時間＋GPS） |
| 地圖 | **Leaflet + OpenStreetMap**，與 `src/layouts/Day.astro` 一致；不使用 Google Maps API |
| 路線 | **OSRM 真實道路路線**；失敗或離線時退回直線，不能壞掉 |
| 畫面 | 手機優先：**上半地圖、下半大字卡片**，按鈕切換即時／預覽，高對比、大字（長輩要看得清楚） |

## 資料現況與需要補的

- 行程資料在 `src/data/itinerary.js`：`trip.days[].activities[]`，每筆有 `time`（"HH:MM"）、`title`、`type`（flight／transport／food／ticket／shopping／hotel）、`gmap`、`nmap`、`budget`。
- **activities 沒有座標。** 只有 `trip.locations[]` 有 `lat/lng`，且只涵蓋部分地點。新頁面需要每一站的座標。
- 座標多數是**約略值**（檔案註解已說明，Working Holiday、母牛肋排家、X the SKY、烤肉的男子、機張刀削麵等都是估的）。**導航用的座標必須先驗證**，否則箭頭會指錯方向。驗證方式：用 Google 或 Naver 搜尋該店，取地圖上的實際座標。
- `trip.timezone` 是 `Asia/Seoul`，`trip.startDate` 是 `2026-10-31`。

### 資料變更

1. 在每個 activity 加 `lat`、`lng`（沿用 `loc()` 的樣式，並驗證）。transport 類的 activity 座標可寫終點，起點取上一站。
2. 新增 `public/data/routes.json`（或同等的 build 產物）：每個「相鄰兩站」一筆，含 `geometry`（GeoJSON）、`distanceM`、`durationS`。
3. 新增一支 build 時執行的腳本（例如 `scripts/build-routes.mjs`），讀 `itinerary.js` 的座標、呼叫 OSRM、寫入 `routes.json`。**路線在 build 時抓好並一起 commit，執行時不依賴 OSRM**；只有缺資料的段落才在執行時嘗試即時抓，抓不到就畫直線。

## 頁面行為

網址：`/live`，加入主導覽。支援 `?day=1|2|3` 與 `?t=2026-11-01T14:30`（預覽用）。

### 即時模式

- 以手機時間換算成 Asia/Seoul 時間，對照 `trip.days[].activities[].time`，找出「**現在**」與「**下一站**」。
- 若現在不在 10/31–11/2 範圍，頁面一開始就預設預覽模式，並提示「行程尚未開始」。
- 用 `navigator.geolocation.watchPosition`，按下按鈕才要求權限；使用者不同意或失敗時，仍可用時間判斷現在／下一站，只是沒有距離與方向。
- 卡片顯示（大字）：
  - 現在：站名、類型圖示
  - 下一站：站名、**方位與距離**（例如「東北方 2.3 公里」，直線）、**路線車程**（OSRM `durationS`，標示為估計）、行程上寫的出發時間
  - 距離下一站出發還剩幾分鐘；若已超過，顯示「已延後 N 分鐘」（不自動改行程）
- 地圖：自己的位置、現在、下一站、當日路線（道路形狀）；下一站有方向箭頭。

### 預覽模式

- 時間軸滑桿（10/31 00:00 到 11/2 23:59，或選一天）。拖動即時更新「現在／下一站」、地圖上的標記和卡片，內容與即時模式相同，只是時間來源是滑桿。
- 「播放」按鈕：自動快轉一天。
- 不使用 GPS。

### 共用

- 當日路線：用 OSRM 路線形狀畫在地圖上，每段不同顏色或用 `DAY_COLORS`（沿用 `map.astro` 的）。
- 站點標記以 `type` 分色或圖示，與現有 icon 對應。
- 「導航」連結：卡片上放 **Google Map** 與 **Naver Map** 兩個按鈕（資料已有 `gmap`、`nmap`），因為韓國 Google 步行／公車導航不準，Naver 是主要實際導航工具。
- 長輩友善：字級至少 18px（卡片主要字 24px 以上）、對比 4.5:1 以上、按鈕至少 48px、不依賴顏色單獨傳達資訊。

## 方位與距離計算

- 距離：Haversine（公尺），顯示 ≥1000 公尺用公里一位小數。
- 方位：從現在位置（或現在那一站）到下一站的初始方位角，換算成 8 方位文字（北、東北、東、東南、南、西南、西、西北）。
- 若沒有 GPS，用「現在那一站」的座標當起點。

## OSRM 注意事項

- 公用示範伺服器（`router.project-osrm.org`）沒有穩定性保證，且只正式支援 driving profile。步行路段（例如西面站到飯店）不要用它畫，直接用直線並標示。
- 本行程約 40 段，一次 build 就夠，**請勿**在每次頁面載入時抓。
- OSRM 的 `durationS` 是無車流的行車時間，**請在卡片上標示「約」並加上 20–30% 緩衝**，或同時顯示行程原先的估計。具體採哪個由實作者決定並寫在頁面上，不要混用不標示。
- 失敗的段落：記錄在 build 輸出，回退直線，頁面顯示「直線距離」。

## 離線與快取

- 現有 `public/sw.js`（`busan-v3`）只快取同源 GET，**不快取 OpenStreetMap 地磚**，所以離線時地圖底圖會空白，但站點、路線、卡片仍可用。這個限制要在 spec 實作時確認並考慮是否加地磚快取（OSM 地磚使用條款限制大量預抓，不建議預抓整個釜山）。
- 把 `/live/`、`/data/routes.json`、Leaflet 的 JS／CSS（若改成同源載入）加入 `sw.js` 的 `URLS`，並更新快取版本號。

## 不在範圍內

- 行程編輯、改順序、重新排程。
- 自動叫車、即時路況、即時公車時刻。
- 多人共享位置。
- 修改 `/map` 與 `Day.astro`（本次只新增 `/live`）。

## 驗收條件

1. 打開 `/live`（桌機與手機視窗），預覽模式拖動滑桿，卡片的「現在／下一站」與 `itinerary.js` 時間一致。
2. 即時模式：模擬時間（`?t=`）與 GPS（瀏覽器開發工具可模擬）下，方位文字與距離正確（至少抽驗 3 組）。
3. 關掉 OSRM（斷網）後頁面仍可使用，路線退回直線，沒有 JS 錯誤。
4. `npm run build` 通過；`routes.json` 涵蓋所有 transport 相鄰段落，缺的有列在 build 輸出。
5. 無障礙：字級、對比、按鈕尺寸達標，可只用鍵盤操作滑桿。
6. 每個 activity 的座標都經過驗證（有來源紀錄），沒有留下約略值。

## 實作者的待確認事項

- 座標驗證要在寫程式前完成，這會影響所有方向與距離。
- OSRM 公用伺服器是否仍可用、速率限制多少。
- 卡片上的車程要採 OSRM 時間（加緩衝）還是行程估計，或兩者並列。
